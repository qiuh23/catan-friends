## 实现及保持的规则

- 比对另外两款游戏 `src/random.js` / `src/shared/random.ts` 的 ChaCha20 与无偏整数实现，以及各自站长权限、举报入口和必要证据白名单。
- 私有流位于 `room.random`；开局地图/港口/基础数字、发展牌、骰子与抢牌都使用它。Fisher–Yates 仍按递减边界交换，未改为随机排序。
- 规则执行使用克隆；房间事务覆盖流、回执和结果。Node 文件提交或 Worker 事务/alarm 失败后恢复；不确认未保存动作。
- 基础版地图重试达到 10,000 次明确失败，不带违规数字继续；5–6 人 A..Zc 环形摆放、跳过双沙漠、配对回合与入座顺序先手保持原样。
- 个人视图、玩家字段及公开事件使用白名单。流不存入 `game`，避免旧游戏对象展开路径意外带出秘密；错误和后台类别不输出原异常对象。
- 聊天不增加棋盘 revision；独立序号与最近 512 条成功请求回执，不挤出游戏 256 条回执。玩家令牌桶容量 5、每 2 秒补 1，随房间保存。断线复用原请求，确认不明后同一草稿重试仍用原 ID；失败保留输入，确认期间新写的内容也保留。
- 举报沿用本轮用户确认的邮箱，用户随后要求一并配置留存，因此源码默认与示例/Worker vars 都为 90 天。管理员密钥缺失时接口关闭；普通聊天是最近 100 条/7 天。处置有明确理由、必要证据、保全与解除，未建设工单系统或 AI 审核。
- Node 独立处置文件和 Worker 独立存储 key 在房间关闭后继续按期限保留审计；恢复旧游戏仍先应用处置。运维备份包含独立记录；部署/回滚使用 schema 3 和首次发布准备门禁，拒绝不执行新语义的旧代码。
